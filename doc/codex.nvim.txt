INTRODUCTION                                         *codex-nvim-introduction*

`codex.nvim` embeds the Codex CLI inside Neovim. It provides:

- session lifecycle commands for opening, focusing, toggling, and closing the
  terminal
- a shared prompt builder for adding text, file references, visual selections
  and skills that can be sent or submitted to as input to codex.
- immediate skill and terminal-input helpers
- `/mention` helpers for files and directories
- wrapper-command helpers for slash commands and `resume`

The authoritative user-facing reference is this helpfile. You should not need
browser Markdown docs for normal installation, configuration, commands, API
lookup, or common examples.

==============================================================================
REQUIREMENTS                                         *codex-nvim-requirements*

- Neovim >= 0.12.0
- `codex` available on your `PATH`, or a custom `launch.cmd`

If `:help codex.nvim` is missing after a local/raw install, generate help tags
for the plugin's `doc/` directory, for example:

>
  :helptags {path-to-codex.nvim}/doc
<

Plugin managers usually do this for you. `:helptags ALL` is the broad fallback.

==============================================================================
INSTALL                                                   *codex-nvim-install*

Example lazy.nvim spec:

>lua
  {
    url = "https://codeberg.org/yaadata/codex.nvim.git",
    version = "2.0.0-alpha.3",
    lazy = false,
    cmd = {
      "Codex",
      "CodexFocus",
      "CodexClose",
      "CodexClearInput",
      "CodexSendSelection",
      "CodexSendFile",
      "CodexMentionFile",
      "CodexMentionDirectory",
    },
    opts = {},
    config = function(_, opts)
      require("codex").setup(opts)
    end,
  }
<

The `cmd` list allows lazy loading on first `:Codex*` command use.

==============================================================================
SETUP                                                       *codex-nvim-setup*

Minimal setup:

>lua
  require("codex").setup({})
<

When using lazy.nvim with `cmd` and `opts`, prefer:

>lua
  config = function(_, opts)
    require("codex").setup(opts)
  end
<

`setup()` registers the `:Codex*` commands and wires the runtime state used by
the public Lua API.

lazy.nvim calls `require("codex").deactivate()` before unloading the plugin.

CONFIGURATION REFERENCE                                    *codex-nvim-config*

The resolved default options table is:

>lua
  {
    launch = {
      cmd = "codex",
      args = {},
      env = {},
      auto_start = true,
      cwd = nil,
    },
    log = {
      level = "warn",
      verbose = false,
    },
    hooks = {
      on_setup = nil,
      on_terminal_open = nil,
      on_terminal_restore = nil,
      on_terminal_close = nil,
    },
    terminal = {
      provider = "auto",
      provider_opts = {
        native = {
          window = "vsplit",
          vsplit = {
            side = "right",
            size_pct = 40,
          },
          hsplit = {
            side = "bottom",
            size_pct = 30,
          },
          float = {
            width_pct = 80,
            height_pct = 80,
            border = "rounded",
            title = " Codex ",
            title_pos = "center",
          },
        },
        snacks = {
          -- pass-through for snacks.terminal(..., opts)
        },
      },
      auto_close = true,
      startup = {
        timeout_ms = 2000,
        retry_interval_ms = 50,
        grace_ms = 800,
      },
      keymaps = {},
    },
  }
<

launch                                                     *codex-nvim-launch*
    Process launch settings.

    `cmd`
      Executable to start. Defaults to `codex`.

    `args`
      Additional CLI arguments appended to `cmd`.

    `env`
      Extra environment variables merged into the process environment.

    `auto_start`
      When true, the terminal can be opened automatically for send-like flows.

    `cwd`
      Working directory override. When nil, use Neovim's current working
      directory.

log                                                           *codex-nvim-log*
    Logging controls.

    `level`
      Log threshold string such as `"warn"` or `"debug"`.

    `verbose`
      When true, capture extra debug-oriented log entries.

hooks                                                       *codex-nvim-hooks*
    Lifecycle callbacks for editor-side customization. All hooks receive one
    context table, run synchronously with protected errors, ignore return
    values, and never abort Codex behavior. Hook errors are logged as warnings.

    Supported callbacks:

      `on_setup`
        Fires after setup has initialized config, state, commands, and autocmds,
        before restore or auto-start can open a terminal.

      `on_terminal_open`
        Fires after a new Codex terminal session starts.

      `on_terminal_restore`
        Fires after codex.nvim reattaches to a restored Codex terminal.

      `on_terminal_close`
        Fires once when a Codex session is torn down or marked dead. Window
        hiding alone is not a close event.

    Context fields:

      `event`
        Hook event name.

      `config`
        Resolved codex.nvim config. Treat as read-only.

      `provider`, `bufnr`, `winid`, `cmd`, `cwd`
        Included when available for terminal lifecycle events.

    Example:
>lua
  local function disable_spell(ctx)
    if type(ctx.winid) == "number" and vim.api.nvim_win_is_valid(ctx.winid) then
      vim.wo[ctx.winid].spell = false
      return
    end

    if type(ctx.bufnr) ~= "number" then
      return
    end

    for _, winid in ipairs(vim.api.nvim_list_wins()) do
      if vim.api.nvim_win_get_buf(winid) == ctx.bufnr then
        vim.wo[winid].spell = false
      end
    end
  end
  require("codex").setup({
    hooks = {
      on_terminal_open = disable_spell,
      on_terminal_restore = disable_spell,
    },
  })
<

terminal                                                 *codex-nvim-terminal*
    Terminal presentation and startup behavior.

    `provider`
      One of `"auto"`, `"snacks"`, or `"native"`.

      `"auto"` prefers `snacks` when available and falls back to `native`.

    `provider_opts`
      Provider-specific configuration. The native provider supports window
      layout control; the snacks provider receives pass-through options for
      `snacks.terminal(..., opts)`.

    `auto_close`
      When true, provider windows auto-close only after the terminal process
      exits.

    `startup`
      Send-queue startup timing.

      `timeout_ms`
        Max time to wait for terminal readiness before dropping queued sends.

      `retry_interval_ms`
        Poll interval while waiting for startup readiness.

      `grace_ms`
        Minimum delay after terminal open before the first send.

    `keymaps`
      Terminal-local mappings. No defaults are registered. See
      |codex-nvim-keymaps|.

native provider                                   *codex-nvim-terminal-native*
    Layout options for the built-in provider.

    `window`
      One of `"vsplit"`, `"hsplit"`, or `"float"`.

    `vsplit.side`
      `"left"` or `"right"`.

    `vsplit.size_pct`
      Integer width percentage, 10-90.

    `hsplit.side`
      `"top"` or `"bottom"`.

    `hsplit.size_pct`
      Integer height percentage, 10-90.

    `float.width_pct`, `float.height_pct`
      Float size percentages, 10-100.

    `float.border`
      Floating-window border style.

    `float.title`
      Float title string.

    `float.title_pos`
      `"left"`, `"center"`, or `"right"`.

snacks provider                                   *codex-nvim-terminal-snacks*
    `terminal.provider_opts.snacks` is passed through to
    `snacks.terminal(..., opts)`.

terminal.keymaps entries                              *codex-nvim-terminal-km*
    Each entry is a table with:

    `mode`
      A string or list of modes accepted by `vim.keymap.set`.

    `action`
      A function to run. For builtins, use
      `require("codex.builtin").keymaps`.

    `desc`
      Optional for builtin actions, required for custom functions.

COMMANDS                                                 *codex-nvim-commands*

Codex[!]                                                    *:Codex* *:Codex!*
    `:Codex` toggles the active Codex terminal or opens one when none exists.
    `:Codex!` force-opens and focuses the terminal.

CodexFocus                                                       *:CodexFocus*
    Focus the active Codex terminal, opening one if needed.

CodexClose                                                       *:CodexClose*
    Close the active Codex terminal session and reset queued sends.

CodexClearInput                                             *:CodexClearInput*
    Clear the active Codex terminal input line by sending `<C-c>`.

CodexSendSelection                                       *:CodexSendSelection*
    Send the active visual selection with file path and line-range context.
    This command is available only from visual mode.

CodexSendFile                                                 *:CodexSendFile*
    Send the current buffer path as an ACP file reference (`@path`).

CodexMentionFile [path]                                    *:CodexMentionFile*
    Send `/mention` for a file path. When `[path]` is omitted, use the current
    buffer path.

CodexMentionDirectory [path]                          *:CodexMentionDirectory*
    Send `/mention` for a directory path. When `[path]` is omitted, use the
    current buffer directory.

LUA API                                                       *codex-nvim-api*

Return conventions                                    *codex-nvim-api-returns*

- Most builder and input actions, plus `session.unfocus()`, return
  `ok, err`: a boolean outcome and an optional error string.
- `input.get()` returns `ok, text`, not an error string.
- Builtin command helpers return `err`: nil on immediate success, or an error
  string on failure. Deferred failures are reported through notifications.
- `builtin.format_skill()` returns `text, err`.
- Query APIs, lifecycle methods, and `prompt_builder.join()` return the values
  documented below. `codex.Outcome` represents boolean success or failure;
  `codex.Error` is `string|nil`.

Access the core API through `require("codex")` and command helpers through
`require("codex.builtin")`. Call methods with dot syntax.

Setup and runtime                                     *codex-nvim-api-runtime*

setup({opts})                                                    *codex.setup*
    Initialize plugin config and runtime state, and register `:Codex*`
    commands.
    Returns: `nil`

deactivate()                                                *codex.deactivate*
    Retire plugin runtime state before unloading or reconfiguring the plugin.
    Closes the active terminal, removes plugin commands and autocmds, and
    invalidates pending work. lazy.nvim calls this automatically on reload.
    Returns: `nil`

get_config()                                                *codex.get_config*
    Return a deep-copied snapshot of the resolved config.
    Returns: `table|nil`

Session                                               *codex-nvim-api-session*
                                                   *codex-nvim-api-lifecycle*

Access session methods through `require("codex").session`.

session.open({focus}, {args})                             *codex.session.open*
    Open a Codex terminal session.
    `focus` defaults to true when omitted. Optional `args` is a string array
    that overrides configured launch arguments.
    Returns: `nil`

session.close()                                          *codex.session.close*
    Close the active session and reset the send queue.
    Returns: `nil`

session.toggle()                                        *codex.session.toggle*
    Toggle the active terminal, or open one when none exists.
    Returns: `nil`

session.focus()                                          *codex.session.focus*
    Focus the active session, or open one when none is running.
    Returns: `nil`

session.unfocus()                                      *codex.session.unfocus*
    Return to the last tracked non-Codex editor location.
    Returns: `codex.Outcome, codex.Error`

session.is_running()                                *codex.session.is_running*
    Return whether the active Codex session is alive.
    Returns: `boolean`

session.is_focused()                                *codex.session.is_focused*
    Return whether editor focus is on the active Codex session.
    Returns: `boolean`

Access log methods through `require("codex").logs`.

logs.get()                                                    *codex.logs.get*
    Return captured in-memory log entries.
    Returns: `codex.LogEntry[]`

logs.clear()                                                *codex.logs.clear*

    Returns: `nil`

Prompt builder                                        *codex-nvim-api-builder*

Access the shared draft through `require("codex").prompt_builder`.
Adding content does not open or focus the terminal. Fragments are concatenated
in insertion order without extra separators; include spaces or newlines in
raw text where needed. The draft is separate from the terminal's prompt input
and from the queue that waits for terminal readiness.

prompt_builder.add({text})                          *codex.prompt_builder.add*
    Append raw text to the shared draft.
    Returns: `codex.Outcome, codex.Error`

prompt_builder.add_file({opts})                *codex.prompt_builder.add_file*
    Append an ACP-style `@path` reference with a trailing space.

    `opts.path`
      Explicit file path. Takes precedence over `opts.bufnr`.

    `opts.bufnr`
      Buffer to resolve when `opts.path` is omitted; defaults to the current
      buffer. The resolved path must identify a regular file.

    Returns: `codex.Outcome`, `codex.Error`

prompt_builder.add_selection({opts})      *codex.prompt_builder.add_selection*
    Append a path reference, selected line range, and fenced code block.

    `opts.line1`, `opts.line2`
      Optional start and end lines.

    `opts.start_col`, `opts.end_col`
      Optional zero-based, inclusive byte columns.

    `opts.bufnr`
      Optional source buffer; defaults to the current buffer.

    `opts.visual_mode`
      Optional `"v"`, `"V"`, or CTRL-V character for characterwise, linewise,
      or blockwise selection.

    When no explicit range is given, use the active visual selection or
    saved visual marks.
    Returns: `codex.Outcome`, `codex.Error`

prompt_builder.add_skill({opts})              *codex.prompt_builder.add_skill*
    Append a literal skill invocation with a trailing space.
    `opts.name` is required; `opts.plugin` is optional. The invocation is
    `$plugin:name ` or `$name `.
    Returns: `codex.Outcome`, `codex.Error`

prompt_builder.clear()                            *codex.prompt_builder.clear*
    Discard the shared draft. Does not clear text already in the terminal
    or cancel payloads already queued for delivery.
    Returns: `codex.Outcome`, `codex.Error`

prompt_builder.peak()                              *codex.prompt_builder.peak*
    Return the current draft fragments as a `string[]`. The method is named
    `peak`, not `peek`. The returned table is the live fragment array, not a
    copy. Clearing or sending the draft replaces that array.

prompt_builder.join({fragments})                   *codex.prompt_builder.join*
    Append each string in `fragments` to the shared draft in order.
    Returns: `nil`

prompt_builder.send()                              *codex.prompt_builder.send*
    Consume the shared draft and send it as one bracketed-paste payload.
    Open a terminal if needed and focus it after successful delivery.
    Does not press Enter.
    An empty draft returns `false, "no queued message"`.
    Returns: `codex.Outcome`, `codex.Error`
      true means sent or accepted into the readiness queue, not necessarily
      delivered. The draft is consumed before dispatch and is not restored if
      dispatch fails.

prompt_builder.submit()                          *codex.prompt_builder.submit*
    Send a non-empty draft, then attempt to press Enter in the active terminal.
    With an empty draft, attempt to submit the existing terminal prompt.
    Returns: `codex.Outcome`, `codex.Error`

    A non-empty draft may queue until the terminal is ready. After the payload
    is written to the terminal channel, Enter is attempted after a 90 ms delay
    by default. Set `vim.g.CODEX_SUBMIT_INPUT_DELAY_MS` to change the delay.
    The delay does not confirm that Codex has processed the text but is a best
    effort at the time for the text to be processed.

Example: compose a prompt and send it without Enter: >lua

  local prompt = require("codex").prompt_builder
  prompt.clear()
  prompt.add("Review this file: ")
  local ok, err = prompt.add_file()
  if not ok then
    vim.notify(err, vim.log.levels.ERROR)
    return
  end
  prompt.send()
<

Input                                                   *codex-nvim-api-input*
                                                        *codex-nvim-api-send*

Access terminal input methods through `require("codex").input`.

input.clear()                                              *codex.input.clear*
    Send `<C-c>` to clear the current terminal prompt input.
    Does not clear the shared builder draft; see |codex.prompt_builder.clear|.
    Returns: `ok, err`

input.copy()                                                *codex.input.copy*
    Focus the active terminal and copy its current prompt input to the
    unnamed register. Return failure when there is no input to copy.
    Returns: `ok, err`

input.get()                                                  *codex.input.get*
    Focus the active terminal and capture its current prompt input.
    Returns: `true, text` when captured, `true, nil` when there is no input,
    or `false` when capture is unavailable or uncertain.

input.feedkey({key})                                     *codex.input.feedkey*
    Encode Neovim key notation and feed it to the terminal with
    `nvim_feedkeys`. Focus or open the session when needed, then attempt to
    return to the tracked editor location if it was initially unfocused.
    Returns: `true`

Slash and wrapper commands                              *codex-nvim-api-slash*

builtin.execute_slash_command({opts})    *codex.builtin.execute_slash_command*
    Capture terminal input, save non-empty input to register `e`, clear the
    terminal input, and send a slash command. Preserve the builder draft and
    restore captured input after sending. This flow does not press Enter.

    `opts.command`
      Required command name, with or without leading `/` characters.

    `opts.args`
      Optional string. Leading and trailing whitespace is trimmed; empty
      arguments are ignored.

    Returns: `err` (`string|nil`). A nil return schedules delivery; it does
    not confirm delivery. Deferred failures produce error notifications.

builtin.format_skill({opts}, {style})             *codex.builtin.format_skill*
    Format a skill invocation without sending it or modifying the draft.
    `opts.name` is required; `opts.plugin` is optional.
    Returns: `text, err` (`string|nil, string|nil`).

    The default format is `$name` or `$plugin:name`, without a trailing space.
    Pass `require("codex.enums.skill_style").SLASH` for `/name` or
    `/plugin:name`. Add any desired separator before appending to the draft.

builtin.resume({opts})                                  *codex.builtin.resume*
    With a running session, send `/resume` through
    |codex.builtin.execute_slash_command|. Otherwise open a focused session
    with resume arguments.

    `opts.harness`
      Defaults to `require("codex.enums.harness").CODEX`: launch `resume`,
      or `resume --last` when `opts.last` is true. Other harness values,
      including `CLAUDE` and `PI`, use `--resume` or `--continue`.

    Returns: `err` (`string|nil`).

Mention helpers                                       *codex-nvim-api-mention*

builtin.mention_file({path})                      *codex.builtin.mention_file*
    Send `/mention` for an explicit file path, or the current buffer path
    when omitted. Uses |codex.builtin.execute_slash_command| to preserve
    prompt input and the builder draft. Does not press Enter.
    Returns: `err` (`string|nil`).

builtin.mention_directory({path})            *codex.builtin.mention_directory*
    Send `/mention` for an explicit directory path, or the current buffer
    directory when omitted. Append a trailing directory separator. Uses
    |codex.builtin.execute_slash_command|; does not press Enter.
    Returns: `err` (`string|nil`).

==============================================================================
COMMAND BEHAVIOR                                 *codex-nvim-command-behavior*

This section captures the user-visible behavior that was previously split
across the Markdown command docs.

Selection sends                                   *codex-nvim-behavior-select*

- `:CodexSendSelection` is visual-only.
- The payload includes a path reference, selected line range, and a fenced
  code block containing the selected text.
- The command clears the shared builder draft, adds the selection, and sends
  it without Enter. Previously accumulated draft content is discarded, even
  if selection extraction fails.
- The command opens a session when needed and focuses it after delivery.

File sends                                          *codex-nvim-behavior-file*

- `:CodexSendFile` uses the current buffer path.
- The path must resolve to a regular file.
- The sent payload is an ACP-style `@path` reference with a trailing space.
- The command clears the shared builder draft before resolving the file.
  Previously accumulated draft content is discarded, even if resolution fails.
- The command sends without Enter and focuses the terminal after delivery.

Mention helpers                                  *codex-nvim-behavior-mention*

- Mention commands accept an explicit path or fall back to the current buffer
  file or directory.
- Paths are normalized to the current working directory when possible.
- Directory mentions are forced to end with a trailing separator.
- Mention helpers use the builtin slash-command flow described below.

Slash commands                                     *codex-nvim-behavior-slash*

- `builtin.execute_slash_command()` accepts `command` with or without `/`.
- Empty or whitespace-only `args` are ignored.
- Input capture focuses the active terminal and must succeed before sending.
- Non-empty prompt input is saved to register `e` before clearing the line.
- The builder draft is temporarily replaced with the command, then restored.
- Command delivery and input restoration use deferred sends with
  `vim.g.CODEX_SUBMIT_INPUT_DELAY_MS` (90 ms by default).
- The current implementation sends without Enter. Captured input is sent
  afterward; these helpers do not confirm that the harness ran the command.

Session opening                                     *codex-nvim-behavior-open*

- Send-like and mention-like flows can auto-open a terminal when needed.
- `:CodexFocus` is the explicit "bring it to the front" command.
- `:Codex` owns the normal toggle behavior; `:Codex!` force-opens and focuses.

KEYMAPS                                                   *codex-nvim-keymaps*

`codex.nvim` does not register global mappings in `setup()`. Define any global
maps in your plugin spec or config.

Example lazy.nvim global mappings:

>lua
  {
    url = "https://codeberg.org/yaadata/codex.nvim.git",
    version = "v2.0.0-alpha.3",
    main = "codex",
    cmd = {
      "Codex",
      "CodexFocus",
      "CodexClose",
      "CodexClearInput",
      "CodexSendSelection",
      "CodexSendFile",
      "CodexMentionFile",
      "CodexMentionDirectory",
    },
    opts = {},
    config = function(_, opts)
      require("codex").setup(opts)
    end,
    keys = {
      {
        "<leader>ot",
        function()
          require("codex").session.toggle()
        end,
        desc = "Codex: Toggle terminal",
        mode = { "n", "v" },
      },
      {
        "<leader>os",
        function()
          local prompt = require("codex").prompt_builder
          prompt.clear()
          local ok, err = prompt.add_file()
          if not ok then
            vim.notify(err, vim.log.levels.ERROR)
            return
          end
          prompt.send()
        end,
        desc = "Codex: Send @{file_path}",
        mode = "n",
      },
      {
        "<leader>os",
        function()
          local prompt = require("codex").prompt_builder
          prompt.clear()
          local ok, err = prompt.add_selection()
          if not ok then
            vim.notify(err, vim.log.levels.ERROR)
            return
          end
          prompt.send()
        end,
        desc = "Codex: Send selection",
        mode = "x",
      },
      {
        "<leader>om",
        function()
          require("codex.builtin").mention_file()
        end,
        desc = "Codex: Mention current file",
        mode = { "n", "v" },
      },
      {
        "<leader>oM",
        function()
          require("codex.builtin").mention_directory()
        end,
        desc = "Codex: Mention current directory",
        mode = { "n", "v" },
      },
      {
        "<leader>or",
        function()
          require("codex.builtin").resume()
        end,
        desc = "Codex: Resume session",
        mode = { "n", "v" },
      },
    },
  }
<

Set `vim.g.mapleader` before plugin setup so `<leader>` expands as expected.

Example terminal-local mappings:

>lua
  local km = require("codex.builtin").keymaps

  require("codex").setup({
    terminal = {
      keymaps = {
        ["<C-c>"] = { mode = { "t", "n" }, action = km.toggle },
        ["<M-BS>"] = { mode = { "t", "n" }, action = km.clear_input },
        ["<C-g>"] = { mode = { "t", "n" }, action = km.unfocus },
